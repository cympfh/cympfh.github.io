14:26:03 Skill紹介

自作だったり絶対入れておきたいスキルを


GitHub - cympfh/skills: Skills for Agents
Skills for Agents. Contribute to cympfh/skills development by creating an account on GitHub.
 
github.com/cympfh/skills

で管理するようにした. skill/ 以下に自作スキルが並んでる（見覚えのあるものを改良しただけのものもある）. 自分自身用には make install すれば skills/ 以下と, 追加で入れたい他のスキルがまとめて最新版がインストールされるようになってる.

作ってよかったスキル

/arxiv-memo

初めて本格的に作ったスキル. arXiv 論文を読む際の「補助教材」を作るスキル. arxiv-mcp と連携させることで arXiv 論文を読むことにしてるが, 実際には arXiv 以外でも気を効かせて読んでくれる. 出力は一枚の Markdown にしてるが, 人間用であれば直接 HTML を出力させても今なら良いかもしれない. 「補助教材」などと言っているが, 本の論文を読まなくてもいいくらいの内容を求めてるので, もはや補助ではない. もともと「忠実な日本語訳」を吐かせるスキルを作ろうとしてたのだが, 著作権を理由に拒否されることが多かったので, 言葉の綾だが「補助教材」と言い換えた.

/bump

作業してるプロジェクト自体のバージョンの数字を上げるだけのスキル. プロジェクトによってバージョンは pyproject.toml だったり Cargo.toml だったりするが, 何によって管理されてるかは AI に任せて, とにかく「前のバージョンからの差分を見て, 適切にバージョンを上げる」ことをしてくれる. 特に SemVer であれば, マイナーバージョンを上げるのか, パッチバージョンを上げるのか等を判断をする必要がある. ただ個人的には最近は全部 CalVer でいいじゃんと思ってるけどね. あと CHANGELOG.md も自動で更新させる. 前回のバージョンとの差分を見るのに使う.

/todo

一番多用してると言える. 人間から AI エージェントへの依頼は普通は Claude Code や Codex といったハーネスを通して行う. ただ仕事中に次のやりたいことを思いついたとき, どこに書く? 今やってる仕事を中断する？ 今やってる仕事とは無関係の場合は？ 新しいハーネスを次に起動しておく？ 私は TODO.md という1ファイルに仕事を積んでる. これは今やってる仕事とは独立に, 非同期に, ただタスクを積むだけのファイル.

# TODO List
## [x] 牛乳を買う [YYYY-MM-DD 完了]
2本買っといて

**作業完了**
買いました

## [ ] バターも買う
1kgお願い

/todo というスキルは TODO.md を読んで一つタスクを取り出して, それを実行する. 実行したら TODO.md を自ら更新してチェックを入れる.

/check

「今から言うのは確認であって, コード変更の依頼ではないよ」ということを念押しするスキル. つい「ここの箇所バグってない？」などと言うと, AI は気を利かせて「ここにはバグがある. 今すぐ修正することが求められている.」として動くことがある. 余談だが人間でもよくあることだ. /check を使うと, コードの修正を禁止する. 発火条件がやや緩く, 逆に今まで通り「ここおかしくない？」に対して勝手に /check を使って「確認だけでコードの編集はしません」と宣言する.

/make

作ったばかりなのでまだ言えないけど, これは発明だと思う. Makefile モドキを AI エージェント向けに書いて, これを解釈実行させるスキル. 擬似 GNU Make を演じさせる.

# Makefile.agent
out.png: input.png
	画像サイズ 1024x1024 に変換して, 人間だけを明るくして

具体的に実行するのは AI エージェントなのでコマンドレシピ部分は自然言語で自由に書く.
